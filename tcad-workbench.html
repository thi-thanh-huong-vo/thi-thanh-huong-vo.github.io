Khởi động trên Linux, chuỗi công cụ, tham số @...@, nút, chạy và các file quan trọng.Starting on Linux, tool flows, @...@ parameters, nodes, running and key files.

Sentaurus Workbench (SWB) là "bàn làm việc" quản lý toàn bộ dự án mô phỏng: chuỗi công cụ, tham số, các thí nghiệm và kết quả. Hiểu SWB giúp bạn chạy hàng chục biến thể thiết kế mà không phải sửa file lệnh bằng tay.

1. Khởi động

ssh -X username@tcad-server      # đăng nhập từ xa, bật chuyển tiếp đồ họa
source /path/to/sentaurus/setup  # nạp môi trường (đường dẫn do quản trị viên cung cấp)
mkdir -p ~/STDB                   # thư mục chứa các dự án
cd ~/STDB
swb &                             # mở Sentaurus Workbench

Đường dẫn cài đặt và cách nạp giấy phép khác nhau giữa các máy chủ; hãy hỏi quản trị viên hệ thống. Nếu kết nối chậm, dùng VNC hoặc một môi trường desktop từ xa thay cho X11.

2. Cấu trúc một dự án

  • Chuỗi công cụ (tool flow): ví dụ SDE → SDevice → SVisual, thêm qua menu Project → Add Tool.
  • Tham số: thêm cột tham số dưới mỗi công cụ, ví dụ Ra (bán kính anode), Nd (pha tạp lớp trôi), T (nhiệt độ).
  • Thí nghiệm (experiment): mỗi hàng là một tổ hợp giá trị tham số. SWB tự tạo các nút (node), mỗi nút là một lần chạy của một công cụ, đánh số duy nhất.

3. Tham số trong file lệnh

Trong file lệnh, viết tham số dưới dạng @Ra@; SWB thay bằng giá trị của từng thí nghiệm trước khi chạy (bước preprocessing). Một số biến đặc biệt:

Cú phápÝ nghĩa
@Ra@Giá trị tham số Ra của thí nghiệm hiện tại
@node@Số nút hiện tại, dùng để đặt tên file đầu ra
@node|sde@Số nút của công cụ sde phía trên trong cùng thí nghiệm
@tdr@, @plot@Tên file mặc định do SWB quản lý
#if … #endifKhối lệnh có điều kiện theo tham số
#if @T@ > 400
  * ở nhiệt độ cao, bật thêm mô hình bẫy
#endif

4. Chạy và theo dõi

  1. Chọn các nút cần chạy, nhấn Run. Màu của nút cho biết trạng thái: đang chờ, đang chạy, xong, hoặc lỗi.
  2. Khi một nút lỗi, mở file log (*_des.log hoặc *.out) để xem dòng lỗi đầu tiên; đừng chỉ đọc dòng cuối.
  3. Tham số trích xuất (ví dụ điện áp đánh thủng) có thể được ghi ngược vào bảng SWB nếu file Tcl của SVisual in ra dòng có dạng DOE: Vbr 1234.

5. Các file quan trọng

6. Thói quen tốt

  • Bắt đầu từ một dự án mẫu trong Sentaurus Training gần với linh kiện của bạn, rồi sửa dần.
  • Thay đổi một thứ mỗi lần, chạy lại, so sánh.
  • Ghi chú phiên bản Sentaurus và các mô hình đã bật cho mỗi kết quả quan trọng; điều này cần thiết khi viết bài báo.
  • Sao lưu dự án (SWB có chức năng xuất dự án thành file nén).

Sentaurus Workbench (SWB) is the "workbench" that manages the whole simulation project: tool chain, parameters, experiments and results. Understanding SWB lets you run dozens of design variants without editing command files by hand.

1. Starting up

ssh -X username@tcad-server      # remote login with graphics forwarding
source /path/to/sentaurus/setup  # load the environment (path from your admin)
mkdir -p ~/STDB                   # folder for projects
cd ~/STDB
swb &                             # open Sentaurus Workbench

Installation paths and license setup differ between servers; ask your system administrator. If the connection is slow, use VNC or a remote desktop instead of X11.

2. Anatomy of a project

  • Tool flow: e.g. SDE → SDevice → SVisual, added via Project → Add Tool.
  • Parameters: add parameter columns under each tool, e.g. Ra (anode radius), Nd (drift doping), T (temperature).
  • Experiments: each row is one combination of parameter values. SWB creates nodes, each one run of one tool, with a unique number.

3. Parameters in command files

In a command file, write a parameter as @Ra@; SWB replaces it with each experiment's value before running (the preprocessing step). Some special variables:

SyntaxMeaning
@Ra@The value of parameter Ra in the current experiment
@node@The current node number, used to name output files
@node|sde@The node number of the upstream sde tool in the same experiment
@tdr@, @plot@Default file names managed by SWB
#if … #endifConditional blocks depending on parameters
#if @T@ > 400
  * at high temperature, switch on the trap model as well
#endif

4. Running and monitoring

  1. Select the nodes to run and press Run. Node colors show status: queued, running, done or failed.
  2. When a node fails, open its log (*_des.log or *.out) and look for the first error line; do not read only the last line.
  3. Extracted values (e.g. breakdown voltage) can be written back into the SWB table if the SVisual Tcl file prints a line of the form DOE: Vbr 1234.

5. Key files

FileContents
sde_dvs.cmdSDE commands (Scheme)
sdevice_des.cmdSDevice commands
*.parMaterial parameters
n*_msh.tdrStructure and mesh
n*_des.pltElectrical data (currents, voltages per step)
n*_des.tdrInternal distributions of quantities
n*_des.logRun log, including error messages

6. Good habits

  • Start from a Sentaurus Training example close to your device and modify it gradually.
  • Change one thing at a time, rerun, compare.
  • Record the Sentaurus version and enabled models for every important result; you will need them when writing papers.
  • Back up projects (SWB can export a project as an archive).
