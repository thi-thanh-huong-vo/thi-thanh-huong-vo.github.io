Quy trình thiết kế, code khởi đầu cho hai dự án nhóm và bảng gỡ lỗi khi ghép hệ thống.A design process, starter code for the two team projects and a debugging table for integration.

Hai dự án nhóm của môn học ghép mọi thứ lại: máy đánh bóng bàn tự động (cảm biến siêu âm, servo, LED) và robot hút bụi tự chế (cảm biến siêu âm, động cơ DC). Bài này đưa ra quy trình thiết kế, code khởi đầu cho từng dự án và cách thử từng phần.

1. Quy trình thiết kế

  1. Yêu cầu và luật chơi: viết ra máy phải làm gì và không được làm gì. Ví dụ luật 1 của dự án bóng bàn: ở trạng thái chờ, vợt không được chắn đường ray bóng.
  2. Chia khối: cảm biến, bộ xử lý, cơ cấu chấp hành, nguồn, khung cơ khí (in 3D).
  3. Thử từng khối riêng: đo khoảng cách bằng HC-SR04 trên Serial Monitor; quét servo bằng Sweep; chạy từng động cơ bằng MotorSpeed. Chỉ ghép khi từng phần đã chạy đúng.
  4. Ghép và chỉnh tham số: ngưỡng khoảng cách, góc, thời gian. Đặt chúng thành hằng số ở đầu file để dễ chỉnh.
  5. Thử trong điều kiện thật và ghi lại kết quả (tỉ lệ đánh trúng, số lần va chạm).

2. Dự án 1: máy đánh bóng bàn tự động

Bóng lăn xuống một đường ray. Cảm biến siêu âm đặt ở cuối ray; khi bóng tới gần hơn một ngưỡng, servo vung vợt đánh bóng rồi trở về vị trí chờ, LED báo hiệu mỗi lần đánh. Một khoảng "nguội" sau mỗi cú đánh giúp cảm biến không nhìn thấy chính cây vợt hay bóng vừa bật ra mà đánh lần nữa.

AutoPingPong.inoChạy thử trên Wokwi ↗
// AutoPingPong.ino -- hit the ball when the ultrasonic sensor sees it coming
// HC-SR04: Trig -> 11, Echo -> 10 ; servo signal -> 9 ; status LED -> 13
#include <Servo.h>

const int TRIG = 11, ECHO = 10;
const int SERVO_PIN = 9;
const int LED = LED_BUILTIN;
const int REST_DEG = 0;            // stand-by angle: must leave the ball rail clear (rule 1)
const int HIT_DEG  = 70;           // swing angle: tune on your own rig
const float TRIGGER_CM = 12.0;     // hit when the ball is closer than this
const unsigned long SWING_MS = 250;     // time the paddle stays out
const unsigned long COOLDOWN_MS = 600;  // ignore the sensor right after a hit

Servo paddle;
unsigned long lastHit = 0;

// Send a 10 us trigger pulse and convert the echo time to centimetres.
// Returns -1 when no echo arrives within 30 ms (nothing in range).
float readCm() {
  digitalWrite(TRIG, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG, LOW);
  unsigned long t = pulseIn(ECHO, HIGH, 30000UL);   // echo pulse width [us]
  if (t == 0) return -1.0;
  return t / 58.2;                                  // round trip at ~343 m/s
}

void setup() {
  Serial.begin(9600);
  pinMode(TRIG, OUTPUT);
  pinMode(ECHO, INPUT);
  pinMode(LED, OUTPUT);
  paddle.attach(SERVO_PIN);
  paddle.write(REST_DEG);
}

void loop() {
  float d = readCm();
  bool ready = (millis() - lastHit) > COOLDOWN_MS;
  if (ready && d > 0 && d < TRIGGER_CM) {
    digitalWrite(LED, HIGH);
    paddle.write(HIT_DEG);         // swing
    delay(SWING_MS);
    paddle.write(REST_DEG);        // back to stand-by
    digitalWrite(LED, LOW);
    lastHit = millis();
    Serial.print("hit at ");
    Serial.print(d, 1);
    Serial.println(" cm");
  }
  delay(20);
}

Nguồn: Viết cho trang này dựa trên bài giảng, dùng tự do

Những thứ cần chỉnh trên máy thật: REST_DEG (vợt nằm ngoài đường ray, theo luật 1), HIT_DEG và SWING_MS (lực và thời điểm đánh), TRIGGER_CM (đánh sớm hay muộn, phụ thuộc tốc độ bóng). Servo tốn khoảng 0,1 s cho 60° với tải nhẹ (tùy loại), nên bóng nhanh cần ngưỡng xa hơn.

3. Dự án 2: robot hút bụi tự chế

Robot đi thẳng; gặp vật cản thì dừng, lùi, quay một góc ngẫu nhiên rồi đi tiếp. Góc ngẫu nhiên giúp robot không bị kẹt lặp lại cùng một đường giữa hai bức tường, và theo thời gian phủ được phần lớn căn phòng.

RobotAvoid.inoChạy thử trên Wokwi ↗
// RobotAvoid.ino -- robot-vacuum style: go forward; at an obstacle back up and turn
const int TRIG = 11, ECHO = 10;
// L9110S / HG7881 dual motor driver
//   driver   Arduino
//   A-1A  -> pin 7    left wheel
//   A-1B  -> pin 6    (PWM ~6)
//   B-1A  -> pin 4    right wheel
//   B-1B  -> pin 5    (PWM ~5)
//   VCC   -> motor battery (+), GND -> battery (-) AND Arduino GND
const int A_1A = 7, A_1B = 6;
const int B_1A = 4, B_1B = 5;

// Send a 10 us trigger pulse and convert the echo time to centimetres.
// Returns -1 when no echo arrives within 30 ms (nothing in range).
float readCm() {
  digitalWrite(TRIG, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG, LOW);
  unsigned long t = pulseIn(ECHO, HIGH, 30000UL);   // echo pulse width [us]
  if (t == 0) return -1.0;
  return t / 58.2;                                  // round trip at ~343 m/s
}

void drive(int a1, int a2, int b1, int b2) {
  digitalWrite(A_1A, a1); digitalWrite(A_1B, a2);
  digitalWrite(B_1A, b1); digitalWrite(B_1B, b2);
}
void forward()  { drive(0, 1, 1, 0); }
void backward() { drive(1, 0, 0, 1); }
void turn()     { drive(0, 1, 0, 1); }   // both wheels the same way = spin in place
void halt()     { drive(0, 0, 0, 0); }

void setup() {
  Serial.begin(9600);
  pinMode(TRIG, OUTPUT);  pinMode(ECHO, INPUT);
  pinMode(A_1A, OUTPUT);  pinMode(A_1B, OUTPUT);
  pinMode(B_1A, OUTPUT);  pinMode(B_1B, OUTPUT);
  randomSeed(analogRead(A5));      // an unconnected pin gives a random seed
}

void loop() {
  float d = readCm();
  if (d > 0 && d < 20) {
    halt();      delay(150);
    backward();  delay(300);
    turn();      delay(random(250, 700));   // turn a random amount
    halt();      delay(100);
  } else {
    forward();
  }
  delay(60);
}

Nguồn: Viết cho trang này dựa trên bài giảng, dùng tự do

Hướng phát triển: thêm cảm biến siêu âm thứ hai đặt chéo để biết nên rẽ bên nào; dùng millis() thay cho delay() để vẫn đo khoảng cách trong lúc lùi và quay; phần hút bụi dùng một quạt nhỏ, nên chú ý thiết kế luồng khí (khí động học cơ bản là một yêu cầu của dự án).

5. Bài tập

  1. Bóng lăn tới cảm biến với tốc độ 0,5 m/s. Servo cần 0,12 s để vợt tới điểm đánh. Nên đặt TRIGGER_CM bao nhiêu nếu điểm đánh cách cảm biến 3 cm?
  2. Viết hàm readCmMedian() trả về trung vị của 5 lần đo để chống nhiễu.
  3. Trong RobotAvoid, vì sao dùng randomSeed(analogRead(A5))?
Đáp án và hướng dẫn

1. Trong 0,12 s bóng đi 0,5 × 0,12 = 6 cm, cộng thêm thời gian đo (cỡ vài ms đến 20 ms mỗi vòng lặp, thêm khoảng 1 cm). Đặt ngưỡng khoảng 3 + 6 + 1 = 10 cm, rồi tinh chỉnh bằng thử nghiệm.

2.

float readCmMedian() {
  float v[5];
  for (int i = 0; i < 5; i++) { v[i] = readCm(); delay(60); }
  for (int i = 1; i < 5; i++) {            // insertion sort
    float x = v[i]; int j = i - 1;
    while (j >= 0 && v[j] > x) { v[j + 1] = v[j]; j--; }
    v[j + 1] = x;
  }
  return v[2];                              // the middle value
}

Trung vị bỏ được các giá trị sai lẻ tẻ (như −1 khi mất tiếng vọng) tốt hơn trung bình. Đổi lại, mỗi lần đọc mất khoảng 0,3 s, quá chậm cho máy bóng bàn nhưng ổn cho robot chạy chậm.

3. random() sinh dãy giả ngẫu nhiên giống hệt nhau mỗi lần khởi động nếu không có hạt giống khác nhau. Chân analog để hở đọc nhiễu điện, mỗi lần một khác, nên dùng làm hạt giống. (Đừng nối gì vào A5 trong dự án này.)

The course's two team projects bring everything together: an automatic ping-pong machine (ultrasonic sensor, servo, LED) and a home-made robot vacuum (ultrasonic sensor, DC motors). This lesson gives a design process, starter code for each project and how to test piece by piece.

1. A design process

  1. Requirements and rules: write down what the machine must and must not do. For example, rule 1 of the ping-pong project: in stand-by, the paddle must not block the ball rail.
  2. Split into blocks: sensors, processor, actuators, power, mechanical frame (3D printed).
  3. Test each block alone: read distances from the HC-SR04 on the Serial Monitor; sweep the servo with Sweep; run each motor with MotorSpeed. Combine only once each part works.
  4. Integrate and tune: distance thresholds, angles, timings. Make them constants at the top of the file so they are easy to change.
  5. Test under real conditions and record the results (hit rate, number of collisions).

2. Project 1: an automatic ping-pong machine

The ball rolls down a rail. An ultrasonic sensor sits at the end of the rail; when the ball comes closer than a threshold, the servo swings the paddle, then returns to stand-by, and an LED flashes for each hit. A "cool-down" after each hit stops the sensor from seeing the paddle itself or the rebounding ball and swinging again.

AutoPingPong.inoTry it on Wokwi ↗
// AutoPingPong.ino -- hit the ball when the ultrasonic sensor sees it coming

What to tune on the real machine: REST_DEG (paddle clear of the rail, per rule 1), HIT_DEG and SWING_MS (strength and timing of the hit), TRIGGER_CM (hit earlier or later, depending on ball speed). A servo takes about 0.1 s for 60° under light load (model dependent), so a fast ball needs a longer threshold.

3. Project 2: a home-made robot vacuum

The robot drives straight; at an obstacle it stops, backs up, turns by a random amount and carries on. The random angle keeps the robot from getting stuck repeating the same path between two walls, and over time covers most of the room.

RobotAvoid.inoTry it on Wokwi ↗

Ways to extend it: a second ultrasonic sensor mounted at an angle to decide which way to turn; millis() instead of delay() so distance is still measured while backing and turning; the vacuum itself uses a small fan, so pay attention to the airflow design (basic aerodynamics is part of the project brief).

4. Debugging the integrated system

SymptomUsual causeFix
The Arduino resets when a motor or servo startsSupply sag from the large start-up currentSeparate motor supply with common GND; 100–470 µF capacitor near the driver
Distances jump around, with zerosNo echo, measuring too often, motor noiseIgnore zeros, take the median of 3–5 readings, cycle over 60 ms
One wheel runs backwardsMotors mounted facing each other or wired in reverseSwap the two motor wires, or swap IA/IB levels in code
analogWrite on pins 9 and 10 does nothingThe Servo library uses Timer1Use other PWM pins for motors (3, 5, 6, 11)
Upload fails with a port errorWrong port, the port is held by another program, charge-only cableReselect Port, close the program holding the port, change cable

5. Exercises

  1. The ball rolls toward the sensor at 0.5 m/s. The servo needs 0.12 s to bring the paddle to the hitting point. What TRIGGER_CM should you use if the hitting point is 3 cm from the sensor?
  2. Write a function readCmMedian() that returns the median of 5 readings to reject noise.
  3. In RobotAvoid, why call randomSeed(analogRead(A5))?
Answers and hints

1. In 0.12 s the ball travels 0.5 × 0.12 = 6 cm, plus the measurement time (a few ms to 20 ms per loop, about another 1 cm). Set the threshold to about 3 + 6 + 1 = 10 cm, then fine-tune by testing.

2.

float readCmMedian() {
  float v[5];
  for (int i = 0; i < 5; i++) { v[i] = readCm(); delay(60); }
  for (int i = 1; i < 5; i++) {            // insertion sort
    float x = v[i]; int j = i - 1;
    while (j >= 0 && v[j] > x) { v[j + 1] = v[j]; j--; }
    v[j + 1] = x;
  }
  return v[2];                              // the middle value
}

The median rejects isolated bad values (such as −1 when an echo is lost) better than the mean. The cost is about 0.3 s per reading, too slow for the ping-pong machine but fine for a slow robot.

3. Without different seeds, random() produces the same pseudo-random sequence after every start-up. An unconnected analog pin reads electrical noise that differs each time, so it makes a good seed. (Leave A5 unconnected in this project.)
